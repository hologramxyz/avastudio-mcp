# Story examples

Three launch films from the library, read beat by beat. Times are approximate. In each one, every demonstration follows one input from the start to its own result. Read them before you write `STORY.md` (step 5). Copy how a story works, never a film's words.

## 1. Granola voice typing (21 s, 1.8M views)

| Seconds | Kind | On screen | The viewer understands |
|---|---|---|---|
| 0–4 | name | "Granola voice typing", a key cap, a waveform pill | a key starts voice typing |
| 4–10 | step + result | the waveform pulses under a text box; the words type in as they are said | hold the key, speak, the words appear |
| 10–13 | claim | "Works in any app", the waveform still on screen | it works everywhere |
| 13–17 | claim | "Unlimited words, for free." "Now available on Mac." | it is free and ready |
| 17–21 | name | the logo draws, then the name | Granola |

- **The input:** the user's voice, drawn as one waveform. It stays on screen from the step to the claims, so the claims are about the same action.
- **The result** is the same words, typed. Nothing else stands in for it.
- **No proof beat.** The working step is the proof; the claims ride on it.

## 2. Claude for Google Workspace (60 s, 13.4M views)

| Seconds | Kind | On screen | The viewer understands |
|---|---|---|---|
| 0–5 | name | "Introducing Claude for Google Workspace" | what it is and where it lives |
| 5–10 | step | the cursor opens Extensions, then Claude, in a document | how to open it |
| 10–19 | step + result | a prompt asks to tighten the summary and make a table; the same document reflows into headings and a table | it edits your document |
| 19–34 | step + result | two CSV files are dragged in; a prompt asks for a report; the same sheet fills with tabs and a chart | it builds a sheet from your files |
| 34–51 | step + result | two connectors are switched on; a prompt asks for a deck; one empty slide becomes a full deck | it builds slides from your data |
| 51–54 | claim | "Claude wherever you work" | it works in every app |
| 54–60 | name | the mark lands, then the name beside it | Claude |

- **The input:** three demonstrations, each with its own prompt and files. Each result appears in the same window its input went into, so the viewer sees cause and effect.
- **Actions are real UI acts:** a menu click, a file drag, a toggle, a send. A screen never just drifts.
- **No numbers.** Three results in a row are the proof.

## 3. Canva Brush (57 s, 2.7M views)

| Seconds | Kind | On screen | The viewer understands |
|---|---|---|---|
| 0–2.5 | problem | "Great takes hundreds of small decisions" | design is hard |
| 2.5–7.5 | claim | a layout breaks into its parts | the model sees each part |
| 8–10.5 | name | "Canva Brush", "Our first vision-language model for design" | what it is |
| 13–16.5 | step + result | a prompt for a pitch deck; the styled deck appears | one prompt, one layout |
| 17–21.5 | proof | "69% Faster", "46% Cheaper" as two bars | it is measurably better |
| 34–42.5 | step + result | one flat label; "mock this label up on an ice cream tub"; the same label on a tub, then a grid of variants | it applies your design |
| 43–46.5 | step + result | a comment "Can we see these for Halloween?"; the same grid turns to Halloween | one note changes everything |
| 51–57 | name | product names, each with its line under it; then the maker's name | the family of models |

- **The input:** the pitch deck at 13 s is a short demonstration of its own; the main one follows one flat label. It travels from the canvas to the tub to the grid to the Halloween set. Every result keeps its name and shape, so the viewer knows it is the same work.
- **The proof** follows the first result and measures that result.
- **Names and lines:** each name sits on its own line, bold, with its line under it.

## What the three share

- In each demonstration one input goes in, and the result that comes out is visibly made from it: the same words, the same document, the same label.
- Each step is an act on the real UI: a key, a click, a drag, a toggle, a comment. Then the result appears in the same place.
- Claims and proof sit next to a working result, never in place of one.
- The end card performs the mark, then the name. A line sits apart from the name, under it or after a clear gap.
